# gitx 发布流程

> **给 AI**: 只在真要发版时读这份 —— 它是操作步骤, 不是背景资料。
> 发布**说明正文**写在 [RELEASE_TEMPLATE.md](../RELEASE_TEMPLATE.md) (顶部到第一个 `---` 之间),
> 每次发版改写它; 本文件只讲"怎么发"。
>
> 本仓库用 `jj` 管理版本 (colocated), 写操作一律用 `jj`, 不要用 git 的写命令。

发版在本地一条命令链完成, **没有 CI**: `uv build` 出两个附件 (wheel + 源码包), 再用
`gitx publish create` 建发行版, 最后下载回来验证装得上。

## 1. 版本与文档

- `pyproject.toml` 的 `version` 与 `src/gitx/__init__.py` 的 `__version__` **必须同时改**成 `X.Y.Z`
  (两处不一致时 `gitx --version` 报的就不是实际发布号)。
- 改写 `RELEASE_TEMPLATE.md` 顶部 (第一个 `---` 之前) 的发布说明; `README.md` 顶部更新本版亮点;
  `skill/gitx/SKILL.md` 的 `version` 同步更新; `INSTALL.md` 若无版本号硬编码则不用动。
- 预发布版本号写成 `X.Y.Z-preN`: uv 会按 PEP 440 归一化成 `rcN`, 构建出的附件名是
  `gitx-X.Y.ZrcN*` —— 不是笔误。

## 2. 构建 (附件恰好 2 个)

```bash
rm -rf dist
uv build --out-dir dist                  # ① wheel + 源码包, 纯 Python 不需要编译器
ls -l dist                               # 应恰好 2 个文件
```

隔离环境实测 wheel 可安装:

```bash
uv venv -q /tmp/gitx-verify
uv pip install -q --python /tmp/gitx-verify/bin/python dist/*.whl
/tmp/gitx-verify/bin/gitx --version
```

> 国内镜像 (如 tuna) 偶发 403 导致依赖装不上时, 可加 `--index-url https://pypi.org/simple`,
> 或退一步用已有的开发 venv: `uv pip install --no-deps --force-reinstall <wheel>`。

## 3. 提交、打标签、推送 (用 jj)

```bash
jj commit -m "vX.Y.Z: <一句话>"
jj bookmark set <分支名> -r @-          # 记着步骤: bookmark 不会自己往前走
jj tag set vX.Y.Z -r @-
jj git push -b <分支名>                 # 记住要跟上 --tag vX.Y.Z (或 --all)
jj git push --tag vX.Y.Z
```

## 4. 创建发行版

```bash
# 说明取 RELEASE_TEMPLATE.md 第一个 --- 之前的内容 (用管道, 别用 <(...) 进程替换: fd 不会传给 gh)
sed -n '1,/^---$/p' RELEASE_TEMPLATE.md \
  | gitx publish create vX.Y.Z dist/*.tar.gz dist/*.whl -T "gitx X.Y.Z" -F -
# 预发布加 -p; 想先建草稿检查就加 -d, 之后 gitx publish edit vX.Y.Z --no-draft 正式发布

# 等价的手工方式:
gh release create vX.Y.Z dist/*.tar.gz dist/*.whl --title "gitx X.Y.Z" --verify-tag --notes-file dist/notes.md
```

## 5. 上传后自检 (附件必须正好 2 个)

```bash
gitx publish view vX.Y.Z                        # 附件清单应该只有 wheel + tar.gz
gh release download vX.Y.Z -p '*.whl' -D /tmp/gitx-check-dl
uv venv -q /tmp/gitx-check && uv pip install -q --python /tmp/gitx-check/bin/python /tmp/gitx-check-dl/*.whl
/tmp/gitx-check/bin/gitx --version
```

## 6. 发完之后

- 用户侧 `gitx upgrade` 查的就是这个 Release, 所以发完即可自更新 (没有额外的分发步骤)。
- 确认 `README.md` 顶部亮点与 `RELEASE_TEMPLATE.md` 的说明跟本版**实际行为**一致 (别写没做的功能)。
